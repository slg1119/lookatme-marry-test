## 접근성

axe-core의 WCAG 2 A/AA 및 WCAG 2.1 A/AA 규칙으로 홈·스타일 미리보기·첫 문항·완료 결과를 각각 검사했습니다. 색 대비 검사를 포함한 **12회 스캔에서 자동 탐지 위반 0개**이며, 마지막 수정 후 추가 데스크톱 홈 스캔도 위반 0개입니다.

첫 실행에서 발견한 옅은 글자 색 대비와 성향 축의 ARIA 역할 문제는 수정 후 재검증했습니다. 최초 근거는 `initial-accessibility-findings.json`, 최종 상세는 각 기기의 `*-accessibility.json`에 있습니다.

종이 질감의 배경 이미지와 일부 모달 요소 겹침 때문에 axe가 대비를 자동으로 결정하지 못한 `incomplete` 항목은 보고서에 그대로 남겨 두었습니다. 자동 탐지 위반 0개는 모든 접근성 요건의 완전한 준수를 뜻하지 않습니다.

## 산출물

- `desktop-preview.png`: 최종 홈 화면 1440 × 1000 미리보기.
- `{desktop,android,iphone}-{home,question,result,shared,preview-modal}.png`: 각 화면 전체 스크린샷.

스크린샷은 폰트 로딩 후 애니메이션을 비활성화하고 CSS 픽셀 크기로 저장했습니다. 데스크톱 홈, iPhone 홈·결과, 다운로드 카드를 직접 이미지로 확인했습니다.

## 검증 범위의 한계

- 모바일 검증은 Playwright의 Chromium/WebKit 에뮬레이션이며 물리 Android/iPhone에서의 검증은 아닙니다.
- OS 공유 시트나 실제 타인에게 전송하는 동작은 실행하지 않았습니다. `navigator.share`를 비활성화하고 클립보드 성공·실패 응답을 제어했습니다.
- 외부 룩앳미 사이트의 신청·결제나 배포 환경 통합은 이 테스트 범위에 포함하지 않았습니다.
- 모든 접근성 수동 검사나 모든 화면의 모든 조작 대상을 망라한 검증은 아닙니다. 위에 나열한 시나리오와 상태를 검증했습니다.
